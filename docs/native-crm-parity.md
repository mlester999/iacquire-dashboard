# Native CRM feature-parity matrix

GoHighLevel is used only as a **functional benchmark** for the CRM capabilities iAcquire's offer needs. Nothing here is a
claim of literal 100% GoHighLevel parity, and no GoHighLevel code, design, branding, API shape or snapshot content was copied.

Status values: `Not implemented` · `In progress` · `Implemented locally` · `Integration verified` · `Production verified` · `Blocked`.
"Implemented locally" means built and covered by automated tests against an embedded PostgreSQL database. A read-only hosted
check on 2026-10-19 found all 61 repository migrations through `0062_agency_manager_blueprint_permissions` recorded in
`public.schema_migrations`, with no pending local migration. The hosted public schema had 258 tables and row-level security
enabled on all 258. The production health endpoint also returned `status=ok` and `database=ok`.

These checks confirm migration and deployment state, not CRM behavior in production. No CRM client workflow or live provider
integration was exercised against production, so no capability in this matrix is marked `Production verified`.

Last updated: 2026-10-19 (Phase 1 and Phase 2: data model, contacts, companies, tags, fields, Smart Lists, pipelines, deals, tasks, imports/exports, permissions, agency workspace, native calendars and booking, booking pages, calendar connections, Website Studio booking; Phase 3: native email/SMS/WhatsApp transports, webhooks, templates and channel setup; Phase 4: workflow engine, follow-ups, agent tools, lead assignment, API and webhooks; Phase 5: forms, campaigns, reviews, calls, reporting, configuration values; CRM Blueprints; Phase 6: GoHighLevel live-record migration, native Setup Center and CRM setup guide, performance indexes, seven-step provider switching, active-switch migration-panel lock, native-channel owner enforcement, capability-aware navigation, and the final RLS rewrite in migration 0060). ## Notes on the rows marked "Implemented locally"

- **1 Provider:** the workspace mode and per-capability owner are enforced in every native write (`assertNativeOwner`), and screens owned by GoHighLevel show a notice instead of editing controls. The seven-step wizard at Settings → CRM Provider chooses, previews, backs up, dry-runs, cuts over, verifies, then completes or rolls back. During a switch, message sends, automations, follow-ups and calendar write-backs pause; iAcquire does not send for a capability owned by GoHighLevel. Native channel activation is refused while GoHighLevel owns conversations, with the reason exposed in channel readiness. Migration-panel actions are locked during a switch and managed through the wizard. GoHighLevel-owned navigation sections carry a badge while their pages remain reachable. A GoHighLevel handoff needs a live location mapping at cutover. Read-rest imports have a lease, record their initiating user, and are dropped if a switch stops; rollback waits for a live worker lease. See [crm-provider-switching.md](crm-provider-switching.md).
- **2–8:** contacts (identities, dedupe, merge, archive, privacy erase, consent), companies, tags, typed custom fields, Smart Lists, notes, timeline and tasks, each with client screens in `/crm` and service tests.
- **9:** native pipelines and deals with a drag-and-drop and keyboard Kanban board, a table, a deal page, idempotent stage moves and metrics computed only from recorded deals.
- **33:** CSV import (mapping, dry run, chunked import, undo) and permissioned, recorded CSV export.
- **34:** GoHighLevel live-record migration reuses the same jobs, rows, chunked worker and undo. It sends GET requests only, to `https://services.leadconnectorhq.com`, refuses the protected Aster Homes and agency locations in code and in the database, and was tested only against a mocked API: no live GoHighLevel call was made. Not migrated: appointments, notes, tasks, conversations, lost-reason names.
- **36:** granular per-person overrides for delegable permissions, mirrored in SQL and TypeScript, plus the Appointment Setter role.
- **37:** agency portfolio of counts only, and a client's CRM opened through a reasoned, time-limited, audited support session that the client can see.

The full local browser matrix uses Playwright against seeded fictional data across the documented roles, routes, desktop and phone widths, and light and dark themes. It records full-page and interaction screenshots and runs axe-core. The exact results and local report paths are in [crm-local-qa.md](crm-local-qa.md); this does not verify the hosted Supabase project or a real provider.
