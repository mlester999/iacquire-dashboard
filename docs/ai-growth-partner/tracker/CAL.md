# CAL — Appointment setting and calendars

Detail for the [Master Completion Tracker](../MASTER_COMPLETION_TRACKER.md). As of commit `6e4a4b7ecbe3d7b0a3a2a41b591cc43d0d59aee9`.

Domain summary (audit of branch claude/ai-growth-partner-completion, HEAD 6e4a4b7e; read-only, no tests or builds run):
- The native scheduling stack is large and real: calendars, appointment types, hosts, availability, public booking pages (/book, /api/public/booking), staff scheduling, hold/approval/booking, reschedule/cancel with snapshot-bound approvals, reminders, and ICS. It runs on the tenant's own Postgres rows with a database exclusion constraint against overlaps, and is covered by database-backed tests (PGlite).
- Google Calendar and Microsoft Outlook adapters, OAuth (PKCE), encrypted token storage, refresh, busy-time polling and event write-back all exist in code. They are SIMULATED in evidence: every test uses a hand-built fetch router; no OAuth app is registered, no real provider call was ever made, and the sync scheduler is documented as not activated in production.
- Sync is one-way each direction, not two-way: external busy times are polled (about 10 minutes, no push) and iAcquire appointments are written to the host's calendar. Remote edits or deletions of those events are not reconciled, and bookings are not re-checked live against the provider.
- The Growth Partner can read availability (Hermes check_availability) and prepare/confirm bookings, reschedules and cancellations only through staff chat with exact ISO-time-plus-exact-contact-name commands and an Approvals step. The Hermes runtime is deliberately never given request_appointment, and it is not told the live booking rules (live-facts skips growth_partner).
- Biggest defects found by code reading: appointment reminders are hard-wired to the legacy appointment_setter agent, so a Growth-Partner-only tenant would have every reminder blocked as agent_missing; no customer notice follows an approved reschedule/cancel or a staff-chat booking; availability fails open when a host's connection breaks or its data goes stale.
- Real-provider acceptance for Google and Microsoft is externally blocked (OAuth apps, verification, credentials, privacy/terms pages, scheduler approval).
- Status labels use IMPLEMENTED — NOT YET VERIFIED where strong real-path tests exist; the orchestrator upgrades after the baseline run.
