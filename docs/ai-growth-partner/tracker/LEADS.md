# LEADS — Lead discovery and live-source readiness

Detail for the [Master Completion Tracker](../MASTER_COMPLETION_TRACKER.md). As of commit `6e4a4b7ecbe3d7b0a3a2a41b591cc43d0d59aee9`.

## Release-candidate update

- Supported discovery paths are OpenStreetMap with optional exact-allowlisted company website reads, the UK Food Standards Agency directory, and workspace CSV intake. Growth Partner launches from Leads and CSV goes straight to the review queue. The source-specific research note describes current behavior and activation dependencies. [Acquisition sources and live-read acceptance](../acquisition-source-research.md)
- Approved map or directory results that lack first-party evidence can now be supplemented in Leads. The workspace reviewer supplies a company page, notes and an attestation. The original listing and the reviewer citation retain distinct provenance. Cross-tenant access is denied, duplicates are rechecked, and the action cannot send messages. An eligible lead can then proceed through lead review and the separate CRM import approval. Open CRM tasks links the imported company to the existing native task form.
- OpenStreetMap results must be inside the approved coordinate box. Approved discovery applies exact saved exclusions before company-site reads and inference. Health reporting marks invalid provider payloads, and Analytics groups approved leads by original source while retaining a distinct synthetic category. Every source reservation must match its linked request, and the worker must hold an active lease for application-run reservations.
- Deterministic provider contracts and synthetic application acceptance exist. Free-text geography/industry inference remains subject to qualification and manual review. Broader regulated and licensed sources, real-source reads and real-model inference remain external approval gates. The per-requirement audit below retains the earlier commit’s evidence and observations.

- What exists: a real, tenant-scoped, DB-backed pipeline from saved targeting through a research job, a closed server-collected source bundle (OpenStreetMap Overpass POI search plus exact-allowlisted company-website reads), model qualification, server-side evidence binding and dedupe, a human review queue, an Approval Center-gated idempotent native CRM import, Work Board and chat notices, audit rows, and per-tenant request/spend ledgers. Sources default to disabled; a Growth Partner run with no enabled source is blocked before any Hermes run.
- Real vs simulated: every source adapter is live-capable code, but all evidence is synthetic. No real Overpass request, no real company-site fetch and no real-model qualification has ever run; the only end-to-end test (tests/ai-growth-partner-fixture-acceptance.test.ts) uses injected fetchers over bundled fictional .test data and a scripted Mock Hermes whose JSON the test builds from the same fixtures. Server guards (binding, caps, duplicate, approval, import, tenant isolation) are exercised on a real PGlite database.
- Channels: only two sources exist in code and in the DB CHECK (openstreetmap, company_website). LinkedIn, Reddit, X, Facebook, Indeed, JobStreet/SEEK, directories and third-party prospecting providers have no adapter and are all Disabled by the 2026-11-04 research decision pending authorization; user-imported lead lists are not built at all (and need no external approval).
- Biggest gaps: (1) targeting is advisory prompt text, not a deterministic filter, and the OSM query is a fixed category dump, so recall for a given ICP is poor; (2) website reads require pre-listing each exact domain, so genuinely discovered businesses land as needs_evidence and cannot be imported; (3) the Leads-page Start research button and scheduled research target the lead_hunter role while the page checks the growth_partner agent, so a Growth-Partner-only client tenant is stuck at waiting_for_agent (static finding, untested); (4) no rejection reasons, aggregate-only review audit, no DB uniqueness on lead domain, no follow-up task after import, and no test asserting zero outbound rows.
- Hard rules hold by design and constraint: leads.outreach_status CHECK 'blocked', consent_status CHECK 'unknown', bundle-mode discards any discovery tool call, bound candidates carry no public contact, import needs an approval. The live-source acceptance harness and the controlled live run do not exist; the run is externally blocked on owner authorization, host/terms review, egress budget and real-model spend.
- Docs vs code: the research note and status doc are candid that no live acceptance has passed; their statements about caps, allowlists and no-fallback match the code. This audit did not run any test or build.
