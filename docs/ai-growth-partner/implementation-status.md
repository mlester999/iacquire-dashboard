Demo copy now describes one AI Growth Partner identity with six retained capabilities; legacy employee records and workflows remain available during staged cutover.

- Growth Partner onboarding now uses the unified questionnaire scope and Partner-specific readiness facts. It creates one runtime identity and generates a non-empty, structured partner configuration from confirmed communication preferences, goals, ideal customers, and protected operating rules. Its control center links to existing workspace controls, filtered by the signed-in member's permissions.

Skipped, unknown, or unconfirmed answers remain excluded or visibly draft; file references and visual assets stay in their asset and knowledge systems rather than becoming employee instructions.
- Acquisition sources now run through the research worker as a closed server-collected bundle. Tenant-scoped OpenStreetMap and exact-domain company-site policies default to disabled. The Growth Partner control center now exposes owner/admin-only source settings with per-job and daily request/spend limits, an explicit enable acknowledgement, empty live endpoint/domain fields by default, and a clear notice that provider caps exclude unmeasured infrastructure costs. The tenant-scoped save action only persists settings and revalidates the page; it never starts discovery. The adapter keeps OSM object IDs, attribution/license and dataset timestamps, checks website redirects, fails closed when robots.txt cannot be checked, and paces requests by host. Source errors stop the run without provider fallback. The worker binds returned candidates and citations to collected evidence before persistence.

It submits the AI review with a matching body marker and header; the local Hermes overlay selects an empty toolset and blocks tool dispatch for that run. If the capability is unavailable, the run stops before discovery. This boundary is covered by local source-runner and overlay unit tests; the pinned Hermes image has not yet been built or exercised in a running gateway.
- The real provisioner acceptance harness now provisions one Growth Partner profile per synthetic tenant and checks one linked partner identity and one permanent conversation per tenant. The synthetic client setup uses the actual tenant-creation and onboarding services, with email delivery captured locally. The harness still requires the pinned Hermes runtime to execute.
