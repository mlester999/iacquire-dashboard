## Harvey reference review

The requested [Harvey repository](https://github.com/ethanplusai/harvey) is MIT-licensed. Useful product patterns are a user-confirmed signal catalog, evidence-backed observations, discovery cost estimates, deterministic filtering, a review Outbox, pre-send checks, stop-on-reply and bounce controls, bounded recurring work, and visible failures. Harvey uses several internal agents; iAcquireOS will not reproduce that identity model or copy its Python runtime. This implementation borrows product concepts only, so no Harvey code or dependencies have been copied. If code is later reused, preserve the MIT license and its required notice and attribution.

## Source activation checklist

Before enabling any external source, record the exact product and endpoint, source purpose, current terms revision and URL, tenant authorization, credentials' tenant binding, numeric rate and concurrency limits, cost model, maximum per-job and daily spend, retention/deletion rules, data fields, provenance, error behavior, and who approved it. If any item is unknown, that source remains disabled. Provider keys, account access, API calls, subscriptions, and paid requests are not authorized by this research note.

## Signal record and execution rules

Every candidate signal must retain the company, source identifier, evidence URL, server-recorded observation time, signal key, extracted evidence, confidence, client-fit explanation, qualification decision, and suggested next action. The system must distinguish a search result from a fact confirmed on the company's own page. Missing, stale, or contradictory evidence remains unknown and routes to review. A score is a research priority, never consent or confirmed interest.

Discovery and contact are separate permissions. A source connection never grants the Growth Partner permission to send a message. Outbound messages, public posts, ads, and campaign launches stay behind the existing specific-action approval path, suppression/opt-out checks, scoped limits, and customer policy. No social platform receives cold automated messages. A source failure, access denial, limit response, or missing budget must stop that source; it must not silently fall back to scraping or another provider.

## Current implementation boundary

The local lead-research workflow validates structured evidence, qualifies candidates, checks duplicates within the tenant, and prepares leads for human review and later CRM handoff. Its research runtime is a connected Hermes agent, not a source-provider adapter with per-source quotas or cost metering. Because no source provider, account, tenant credential, or spend cap has been approved, this worktree has not made provider calls or enabled a paid source. Runtime acceptance still needs an owner-selected provider and isolated test account, followed by evidence that the source limits and actual costs are enforced.
