Conventions that matter when resuming:

* Edit files with the editor tools; shell heredocs and `sed` mangle backslashes (this broke a regex in `src/server/env.ts` and one on master). Re-read every regex you write.
* Do not edit a worktree while a vitest or build run is using it. Run heavy commands through `node scripts/run-locked.mjs heavy -- <command>` (tests: `test`, typechecks: `tsc`).
* The gates, as run for Wave 1: `node scripts/run-locked.mjs tsc -- node node_modules/typescript/bin/tsc -p tsconfig.clean.json --noEmit` and the same with `tsconfig.scripts.json`; `node scripts/run-locked.mjs heavy -- node node_modules/eslint/bin/eslint.js .`; `node scripts/run-locked.mjs test -- node node_modules/vitest/vitest.mjs run --reporter=dot`; `node scripts/run-locked.mjs heavy -- node scripts/build-clean.mjs --webpack` (**the `--webpack` flag is needed in this worktree**: the default Turbopack build cannot resolve `next` through the `node_modules` junction); `node scripts/run-locked.mjs test -- node scripts/rehearse-combined-migrations.mjs`; `python -I scripts/eol-scan.py <base> WORKTREE`.
* `python -I scripts/eol-scan.py <base> WORKTREE` finds files whose line endings flipped (the Write tool can do that); `--fix` repairs them. New files are LF.
* Tests run on embedded Postgres (PGlite); `tests/support/messaging.ts` (`messagingOrg`), `tests/support/crm.ts` (`crmOrg`) and `tests/support/social.ts` are the fixtures. A phone number used in tests must be unique across the process. The database allows one agency workspace. A test may not open a socket to another machine (`tests/support/no-network.ts`).
* Browser-side contracts are guarded by tests because Node tests cannot see them (decision D57): never export a function or constant from a `"use client"` file that server code calls; nothing under `src/lib` that a client component imports may read `node:*` or `src/server`; a public form posted natively from a no-referrer page arrives with `Origin: null`, so use `src/server/security/same-site.ts`. Run `tests/client-bundle-safety.test.ts` alone after touching a component, a page or a library file.
* Browser QA: `scripts/run-inbox-qa-seed.mjs`, then the phase seeds, then `scripts/inbox-qa.mjs` (port 3270) in the background; sign in through a local cookie bridge so no password passes through the chat; temporary helpers go in `public/dev/` and are deleted afterwards. A throttled pane never completes React's streamed reveal: run `window.$RV(window.$RB)` first. Trust DOM measurements over screenshots. The full recipe is in `handoff.md`.
* Money: use `src/lib/money` (integer minor units, exponent-aware). Never floats. Dates a person sees or a seed computes belong to the workspace's time zone (`todayIn` in `src/lib/invoices/state.ts`), not the UTC date.
* Production commands (only on approval): back up with `pg_dump` (`C:\Program Files\PostgreSQL\18\bin`), `migrate.ts --dry-run`, then `--only <version>` one at a time with `ALLOW_REMOTE_DB_IN_DEV=true DATABASE_SSL_CA_FILE=<main>/certs/prod-ca-2021.crt node --env-file=<main>/.env --conditions=react-server --import tsx scripts/migrate.ts`. Section F of `scripts/rehearse-combined-migrations.mjs` prints the checks to make after each step.
